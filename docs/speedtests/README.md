# Speed tests

Data2G's throughput against VARA HF and PACTOR on the channel models of the
IONOS SIM paper, from 40 dB down to −5 dB SNR:

- **AWGN**: additive white Gaussian noise (the paper's WGN).
- **MPG**: CCIR "good" multipath, simulated with 2 rays (the paper's MPG 2).
- **MPP**: CCIR "poor" multipath, simulated with 2 rays (the paper's MPP 2).

## Results

- [2300 Hz: Data2G vs VARA HF 2300 and PACTOR 4](vara-2300.md)
- [500 Hz: Data2G BW500 vs VARA HF 500 and PACTOR 2](vara-500.md)

The charts and tables are generated by [`make_charts.py`](make_charts.py).

## Re-running the sweep

Re-sweep before a release with significant modem or ARQ changes, and commit
the new values with the release.

1. Freeze the commit being released in a worktree of its own (a sweep runs
   for hours; the checkout must not change under it):

       git fetch origin
       git worktree add --detach .claude/worktrees/speed-<sha> origin/master
       cd .claude/worktrees/speed-<sha>

2. Build the C++ core there (the sweep runs native, as every published one
   since the native port):

       tools/build_native.sh

3. Run all 60 points of `scripts/cpu_profile/paper_points.txt` (each point:
   seeds from 0 until 5 transfers complete or 10 fail; ~1.1 GB a job):

       JOBS=12 scripts/cpu_profile/speed_sweep.sh . runs/speedtrials

   It finds the main checkout's `.venv` when the worktree has none. A point
   with a finished report is skipped, so a stopped sweep resumes. `NATIVE=0`
   runs the Python reference instead (much slower; not what is published).

4. Compare with the published values; `--arrays` prints the new `data2g`
   lists for `make_charts.py`:

       python docs/speedtests/compare.py runs/speedtrials --arrays

   Seeds are fixed, so a point whose code path did not change repeats to the
   byte. Points marked `<--` moved 5% or more, or had a failed transfer:
   say in the commit which change moved them.

5. Paste the arrays into `make_charts.py`, run it, and commit the charts and
   pages with the commit swept and the notable changes in the message.
